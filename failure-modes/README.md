# Failure modes

Before/after renders of bugs fixed in this repository. Each pair is named
after the short hash of the commit that fixed it (plus a slug when one commit
fixed several): `<hash>-before.png` is the render at that commit's parent,
`<hash>-after.png` the render at the commit. A change that renders nothing
differently gets one image instead of a pair, `<hash>-<slug>.png`: the output
of the new reader on a real file.

| Commit | Failure |
| --- | --- |
| `ac63897` | Group 3 fax stream with fill bits before every end-of-line pattern and `/EndOfLine` unset decoded zero rows; the page's only image was skipped as truncated and painted as zero samples — a solid black page under `/DeviceGray`. |
| `2ddb64f` (text-state) | Character spacing set inside `q`/`Q` leaked into the runs that followed: text state parameters (`Tc`/`Tw`/`Tz`/`TL`/`Tf`/`Ts`) were held per content stream instead of in the graphics state, so Quartz-generated pages — one `q BT … Tc … ET Q` bracket per run — rendered later runs with inflated advances that overlapped the next run's absolute position. |
| `2ddb64f` (cmyk) | DeviceCMYK→RGB used the additive `1 − min(1, ink + K)`, saturating every channel of a deep color to zero: the rich navy boxes of this financial report painted pure black. The multiplicative `(1−ink)·(1−K)` keeps the hue. |
| `9bf1ee9` | TIFF predictor 2 was undone for 8-bit components only, so a 16-bit gray image stored with `/Predictor 2` painted its raw differences: a black square with stray edges instead of the gradient. The fix adds 16-bit components as big-endian values and sub-byte components inside their packed bytes. |
| `c61139f` (decode) | JPEG samples skipped the `/Decode` array and the `DCTDecode` `/ColorTransform` parameter was never read. Left: a Photoshop-style CMYK JPEG (stored as 255 minus ink, `/Decode [1 0 1 0 1 0 1 0]`) painted solid black instead of cyan, magenta, yellow and black. Right: an RGB JPEG stored without the YCbCr transform under `/ColorTransform 0` painted false colours instead of red, green, blue and gray. |
| `c61139f` (adobe-rgb) | A three-component JPEG whose Adobe APP14 flag says no colour transform, but whose component ids are 1, 2, 3, was decoded as YCbCr because the decoder crate consults the ids first: the USDA GAIN Report globe on this page painted magenta. The marker's flag now wins, as Table 13 says, and the globe is blue. |
| `c61139f` (separation) | The special Separation colorants went through the alternate space and tint transform like any other name. Left column: a fill, a stroked frame and a stencil mask in `/Separation /None` painted black through a transform that maps every tint to black; the standard says None never marks the page, and they are gone. Right column: fills in `/Separation /All` at tint 1 and 0.5 painted white through a transform that maps every tint to white; All puts the tint on every colorant, so they are black and mid-gray. |
| `c61139f` (cid) | A `CIDFontType0` whose CFF program has no CIDFont operators got an empty CID-to-GID table, so every CID landed on gid 0 and the title of this membership form (pdf.js bug1669099) was missing. Such a program uses the CID directly as the glyph index (ISO 32000-1 9.7.4.2), and the title is back. |
| `c61139f` (opentype) | A `FontFile3` holding an OpenType container (`OTTO`) was refused because the CFF parser read only bare programs, so this page (pdf.js issue6782) rendered blank. The container's `CFF ` table is the program, and the sentence paints. |
| `0735882` (caps) | Every line cap was round: the stroker never read the `J` operator or `/LC`. Left column, three lines of width 12 between the gray guides under `0 J`, `1 J` and `2 J`: butt caps now stop at the guides and projecting square caps extend the full band past them. Middle column, zero-length dashes (`[0 16] 0 d`) under the same three caps: butt paints nothing, round paints dots, square paints squares along the path. Bottom row, degenerate subpaths (`m l` at one point, `m h`): the path builder dropped them, so nothing painted even under round caps; they paint a dot under round caps only, as ISO 32000-1 8.5.3.2 says. |
| `0735882` (joins) | Every line join was a round fan: the stroker never read the `j` operator, `/LJ`, `M` or `/ML`. Top row, an L of width 12 under `0 j`, `1 j`, `2 j`: the corners are now mitered, round and beveled. Bottom row, a sharp V (miter ratio 2.24) under the same three joins: the miter reaches its point, the bevel is flat. Right, the V under `2 M`, `2.3 M` and `10 M`: the limit of 2 cuts the miter to a bevel, the other two keep it; the two L's under `2 M` and `1.5 M` keep their miters because a right angle's ratio is 1.41. |
| `0735882` (skew) | A join chose each band's outer edge by the offset's angle to the other segment, which is only right while offsets are perpendicular to their segments. Under `2 0 0 0.5 0 0 cm` the pen is an ellipse and the offsets skew, so one band got its inner edge and the miter tip flew along the path: the stroked Bezier circle and the polyline on this page grew spikes at every flattened vertex. The side now comes from the turn's sign, and the ellipse is clean. |
| `6b19fba` (modes) | Text rendering modes 1, 2, 5 and 6 painted the glyphs as plain fills and modes 4 to 7 never touched the clip. Top line, a TrueType face under `0 Tr`, `1 Tr`, `2 Tr` with a blue fill and a red 2-unit stroke: the second word is now stroked only and the third filled then stroked. Bottom, `7 Tr` text followed by four colour bars inside `q`/`Q`: the bars used to paint across the page; they now show only through the glyphs, and the rule drawn after `Q` runs the full width because the clip was restored. |
| `6b19fba` (clip) | pdf.js `text_clip_cff_cid.pdf`: a CID-keyed CFF font shown in mode 7 and a blue rectangle filled over it. The rectangle painted whole before; the clip now cuts it to the glyphs. |
| `6b19fba` (grid) | `/Interpolate` was never read, so an image drawn larger than itself always painted blocks. The same 4x4 image twice, plain on the left and with `/Interpolate true` on the right: the right copy now blends between its samples. |
